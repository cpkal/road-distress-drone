# Spec 002: Show detections on the map

Status: approved. Read AGENTS.md and DESIGN.md first. Depends on spec 001 being built (uploads, frames, detections, and the frame image endpoint).

## Goal

Show all saved detections that have a location on a full-screen dark map. The user can filter them, click one, and see the frame with the damage outlined and the key details.

## Behavior

**App shell & Map (`/` main canvas)**
- Persistent full-screen MapLibre map, client-only, using the dark basemap from runtime config. Keep the map attribution visible (it is required by the tile provider).
- Desktop (`md` and up) has the left navigation rail (`Map`, `Uploads`, `Settings`), the map as the main area, and a side panel displaying the active section (`Map` filters/cluster list/detection details, `Uploads`, or `Settings`). Phone (below `md`) has the map filling the screen, a bottom navigation bar, and a bottom sheet for the active panel.
- On load, fetch detections and fit the map to their bounds. With no detections, show the empty state with an action to open `Uploads`. Use the default center/zoom from runtime config.
- Detections come from a GeoJSON source with clustering on (`cluster: true`, radius about 50, no clustering above zoom 14).
- **Clusters:** a circle with the count in the middle. Clicking one zooms in. If it can't zoom further, show its detections as a list in the panel.
- **Single detections:** uniform-sized circles colored by distress class (`DISTRESS_CLASSES`). Read the colors from the Vuetify theme tokens (see DESIGN.md). Never hardcode hex values in map code. Pair marker colors with the map legend and class labels/icons in the UI so distress classes are never conveyed by color alone.
- Clicking a detection selects it: the marker gets a highlight ring and the detail view opens.
- Detections without a location don't appear on the map.

**Detail view** (side panel on desktop, bottom sheet on phone, per DESIGN.md)
- The frame image with the bounding box drawn on top, using the normalized bbox. If the image fails to load, show a placeholder.
- Distress class chip (label, icon, and theme color), confidence as a percentage.
- Coordinates (lat, lon), capture time (formatted date/time for photo timestamps `> 1e9`, or `mm:ss` video offset), and the source filename (`source_file`).
- A location note when relevant: `"Angled photo, lower accuracy"` when `oblique` is true, or `"Approximate location"` for video uploads (`upload_kind === 'video'`).

**Filters**
- Distress class (multi-select chips with icon + label + color) and upload (single select formatted as `<source_file or kind> (#<short_id>)`).
- Changing a filter refetches from the API and updates the map source. Don't filter on the client, because cluster counts must match what's shown.
- A "Reset filters" button. Show a "No detections match" state when the result is empty.

**Legend:** distress class colors with their labels, placed so it doesn't overlap the navigation bar or bottom sheet.

**States:** loading, empty, error (with a retry button), and a WebGL-unavailable message, as DESIGN.md requires.

## API (new, built on spec 001)

- `GET /detections`: GeoJSON `FeatureCollection`, `[lon, lat]` order. Only detections with a location (`location IS NOT NULL`). Query params (all optional): `class` (repeatable `DistressClass`), `upload_id` (`UUID`). Returns at most 10,000 features and sets `truncated: true` (`false` otherwise) on the collection if it was capped. Each feature's `properties` has: `id`, `class`, `confidence`, `upload_id`.
- `GET /detections/{id}`: full details: `id`, `class`, `confidence`, `bbox`, `location` (`GeoJSONPoint | null`), `location_accuracy_m`, `oblique`, `timestamp`, `source_file`, `upload_id`, `upload_kind`, `upload_created_at`, `frame_id`, and `image_url` (`/frames/{frame_id}/image`).
- Regenerate the TypeScript client after adding these.

## Config

- `NUXT_PUBLIC_MAP_STYLE_URL`: default `https://basemaps.cartocdn.com/gl/dark-matter-gl-style/style.json` (free, no API key)
- `NUXT_PUBLIC_MAP_DEFAULT_CENTER` (`lon,lat`) and `NUXT_PUBLIC_MAP_DEFAULT_ZOOM`: set these to your survey area in `.env`

## Edge cases

- Overlapping detections at the same spot: handled by clustering and the cluster-list fallback above.
- More than 10,000 detections: show a notice that results are capped and suggest using the filters.
- A detection with a missing frame image: the detail view still works, without the image.
- Filter values that no longer exist (for example a deleted upload): treated as "no match", not an error.

## Out of scope

- Satellite imagery, heatmaps, drawing the drone's flight path, loading only the visible viewport, editing or deleting detections, exporting, shareable URLs for a selected detection, severity levels, and light theme.

## Acceptance criteria

- `uv run pytest`, `ruff`, `pnpm typecheck`, and `pnpm lint` all pass.
- API tests cover: each filter, no-location detections excluded, the 10,000 cap with `truncated`, and `[lon, lat]` coordinate order.
- Manual check with real data from spec 001:
  - Points land on the correct road, and one photo's coordinates in the detail view match `exiftool`'s output.
  - Zoomed out, points cluster. Clicking a cluster zooms in.
  - The detail view shows the frame with the box on the damage.
  - Each filter changes both the points and the cluster counts.
  - At a 360px-wide viewport, navigation is a bottom bar, details open in a bottom sheet, and nothing overlaps.
  - The basemap loads without an API key and its attribution is visible.
